Những thay đổi cần thực hiện (chi tiết kỹ thuật)

Data source / API
Khi trang load mặc định: gọi endpoint được xác thực để lấy tất cả booking của user hiện tại. Sử dụng /bookings/user hoặc endpoint tương đương (có sẵn trong api.ts là bookingsAPI.getByUser()); truyền query params hỗ trợ: page, per_page, status, from, to, room_type, search.
Khi user chủ động tìm kiếm (form submit hoặc thay đổi filter): dùng cùng endpoint authenticated /bookings/user (không dùng public search) và gửi params: search, status (tab), from, to, room_type, page, per_page. Điều này đảm bảo kết quả giới hạn trong user.
Nếu API backend không hỗ trợ filter trên /bookings/user, fallback: gọi /public/bookings/search nhưng kèm user identifier từ token (nếu backend hỗ trợ) — nếu không có cách an toàn, yêu cầu backend thêm filter user_only=true hoặc endpoint /bookings/user/search. (Prompt cho BE change nếu cần.)
Room types
Lấy danh sách loại phòng từ GET /reception/room-types (sử dụng helper roomTypesAPI.getAll() trong api.ts), map sang { id, name } và populate Select options.
Khi người dùng chọn room_type, gửi room_type (id hoặc slug theo BE contract) trong query params của /bookings/user.
Date range filter
RangePicker trả về dayjs; chuyển sang string format YYYY-MM-DD (hoặc format backend mong muốn) và gửi from/to trong query params.
Quy ước: gửi from = startOf('day'), to = endOf('day') nếu backend expects inclusive range (document in PR if backend expects otherwise).
Coupon hiển thị
Theo COUPON_API_DOCUMENTATION.md: sử dụng GET /api/coupons/my-redemptions để lấy danh sách coupon đã dùng của user (field booking_code có trong response).
Khi load danh sách booking hoặc detail: merge coupon data bằng booking_code (hoặc booking_id) và hiển thị tóm tắt coupon trên hàng table (ví dụ: badge "VIP300K: -300.000₫") và phần chi tiết coupon trong Drawer (code, description, amount_saved, redeemed_at).
Nếu booking detail từ backend đã bao gồm coupon info, ưu tiên dùng field đó; nếu không, gọi /api/coupons/my-redemptions một lần và cache map booking_code -> couponEntry.
Ngữ cảnh bảo mật
Trang này chỉ trả data của user hiện đăng nhập. Không dùng public search để xem booking người khác.
Đảm bảo tất cả các request quan trọng dùng axios instance có Authorization header (dùng api/axiosInstance hiện có).
Xử lý ngày ISO microseconds
Trước khi parse với dayjs, strip microseconds bằng regex (ví dụ: replace(/.\d+Z$/, 'Z')) hoặc dùng dayjs plugin nếu backend đồng nhất.
UI / UX
Mặc định khi vào trang: hiển thị paginated table của tất cả booking của user (tab All), có tabs theo status.
Search vẫn tồn tại (SĐT, mã booking), nhưng nếu tìm mã/SĐT không thuộc user thì hiển thị “Không tìm thấy”.
Hiển thị coupon tóm tắt trong table và chi tiết coupon trong Drawer.
Giữ các nút hành động (cancel/extend/reschedule/review) như hiện tại, nhưng mọi thao tác phải xác thực và chỉ áp dụng trên booking của user.
Tests & Validation
Thêm unit/smoke tests (vitest/jest) hoặc at least manual test steps:
Default load: /bookings/user được gọi; table hiển thị only user bookings.
Search by date-range: chọn ngày, backend request includes from/to formatted; results correct.
Room-type select is populated and selecting it sends room_type param.
Coupon mapping: after calling /api/coupons/my-redemptions, verify that booking rows show coupon info.

Contract / example requests & responses to implement

GET /bookings/user?search=...&status=...&from=YYYY-MM-DD&to=YYYY-MM-DD&room_type=...&page=1&per_page=20
Response: same shape as SearchResponse (data[], meta) but only for the authenticated user. If backend returns plain array, adapt accordingly.
GET /reception/room-types -> response.data (array) -> map to options
GET /api/coupons/my-redemptions -> Response (see COUPON_API_DOCUMENTATION.md) with booking_code, amount_saved, redeemed_at -> merge by booking_code.
